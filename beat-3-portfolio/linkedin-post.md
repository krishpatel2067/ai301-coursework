# LinkedIn Post

The past few weeks, I opened a fix for my first open-source contribution. I built a new GitHub
workflow for the repository swisspost/design-system that automatically fills in an issue's actual
time spent from the estimated time when the issue gets closed. This means that an issue took as long
as initially expected unless otherwise stated.

It was a tightly scoped issue, but I still learned a lot throughout the process:

- GraphQL: This is a querying language that lets clients ask exactly for the data they need - no
  more, no less. I went from having zero experience to some readability, enough for understanding my
  contribution but an inviting launchpad for a deeper dive of the language in the future.

- Claude skills: With some existing scaffolding, I built skills to grade an issue's fit to my
  preferences, my plan to fix an issue, my PR draft before posting it, and more. I learned to be as
  objective as possible to keep grading consistent across runs.

- Contribution etiquette: As an outside contributor on a repo, I learned the importance of following
  the contribution guidelines closely, respecting repo conventions, and keeping communication
  professional.

As of now, the PR is still open with no maintainer feedback yet. However, this isn't the end: I plan
to consistently monitor the thread to address any comments and make necessary changes.
